# אוצריא ווב (פרויקט התחלתי)

גרסת אתר בהשראת העיצוב והפונקציות של [אוצריא](https://github.com/Sivan22/otzaria) — קורא ספרים בלוח כפול עם
גלילה מסונכרנת, חיפוש, סימניות, וסנכרון ספרייה מול GitHub Releases.

**חשוב לדעת מראש — מה זה כן ומה זה עדיין לא:**

| חלק | מצב |
|---|---|
| ממשק אתר (HTML/CSS/JS), עיצוב בהשראת אוצריא | ✅ עובד, אפשר להריץ מיד |
| קורא דו-לוחי עם גלילה מסונכרנת, סימניות, חיפוש | ✅ עובד על נתוני הדמו |
| שרת Node/Express עם API אמיתי | ✅ עובד |
| מודול סנכרון שמדבר בפועל מול GitHub Releases API | ✅ קוד אמיתי, לא מדומה |
| **כל ~7,000 הספרים מהספרייה האמיתית** | ❌ עדיין לא — יש כאן 3 ספרים לדוגמה (בראשית עם רש"י, משנה אבות, ברכות) |
| פענוח ה-DB (`seforim.db`) לספרים בפועל | ❌ שלב הבא — תלוי בסכמת הטבלאות של SeforimLibrary |
| אחסון בפועל בהיקף גיגה-בייטים + אינדקס חיפוש מלא | ❌ דורש שרת אמיתי (לא ריצה חד-פעמית בצ'אט) |

בקיצור: זה שלד פרויקט אמיתי ועובד, לא הדמיה. אבל "אתר מלא עם כל התוכן" בפועל
הוא פרויקט של שבועות עבודה סביב פענוח מסד הנתונים, אחסון, ותשתית — לא משהו
שאפשר לייצר במלואו בבת אחת.

## מבנה הפרויקט

```
otzaria-web/
├── public/              # frontend סטטי
│   ├── index.html       # דף בית — קטגוריות + חיפוש גלובלי
│   ├── reader.html       # קורא דו-לוחי
│   ├── css/style.css
│   ├── js/library.js    # שכבת גישה לנתונים (מקומי/API)
│   ├── js/app.js
│   ├── js/reader.js
│   └── data/library.json # נתוני דמו (3 ספרים, רשות הרבים)
├── server/
│   ├── index.js         # שרת Express: /api/library, /api/search, /api/sync
│   └── sync.js          # סנכרון אמיתי מול GitHub Releases API
└── package.json
```

## הרצה מקומית

```bash
npm install
npm start
# האתר עולה על http://localhost:3000
```

## איך עובד הסנכרון (server/sync.js)

מיישם את אותו דפוס שאוצריא עצמה משתמשת בו:

1. `GET /api/sync/status` בודק מול `GET https://api.github.com/repos/<REPO>/releases/latest`
   אם יש גרסה חדשה מהגרסה המקומית השמורה.
2. `POST /api/sync/run` מוריד **דלתא** (`patch-vX-vY.db.zst`) אם קיימת בין הגרסה
   המקומית לגרסה החדשה, ואם לא — מוריד את מסד הנתונים המלא (`seforim.db.zst`).
3. מפענח את הקובץ עם הבינארי `zstd` (`apt install zstd` בשרת).
4. **שלב שעדיין חסר בכוונה:** טעינת ה-`.db` (SQLite) בפועל לספרים גלויים
   באתר. זה דורש לבדוק את סכמת הטבלאות בפועל מול
   [SeforimLibrary](https://github.com/Otzaria/SeforimLibrary) (היא יכולה
   להשתנות בין גרסאות), ואז שימוש ב-`better-sqlite3` כדי לקרוא ולמפות
   לפורמט ה-API הקיים (`/api/library`, `/api/search`).

הגדרת `GITHUB_TOKEN` בסביבה מומלצת — GitHub מגביל בקשות אנונימיות ל-60 בשעה.

## הצעדים הבאים למי שממשיך מכאן

1. `npm i better-sqlite3` ולכתוב מודול שקורא את ה-DB המפוענח ומחליף את
   הקריאה מ-`data/library.json` בקריאה מה-DB האמיתי.
2. להריץ `npm run sync` מול הריפו האמיתי כדי לבדוק בפועל את שמות ה-assets
   (ייתכן ששמות הקבצים המדויקים משתנים — צריך לוודא מול release אמיתי).
3. אינדקס חיפוש מלא (למשל SQLite FTS5, או Tantivy כמו שהאפליקציה המקורית
   עושה) במקום הסריקה הנאיבית שקיימת כרגע בקוד ההדגמה.
4. אחסון קבוע — שרת עם מספיק דיסק לגיגה-בייטים של ספרים, ולא ריצה זמנית.
